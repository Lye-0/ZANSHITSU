# ゲームの構造

React + TypeScript + Vite の静的アプリケーション。描画は方向別・対象別の写真と、表面に位置合わせしたHTML/SVGの部品。

## 状態と進行

`GameState` は部屋、面、元の壁 `wallFace`、解除済みの仕掛け、所持品、取り付け済みの部品、各機構の途中状態、発見した手掛かり、ヒント閲覧段階、経過時間、表示設定を保持する。`turnView` が壁→天井→同じ壁、壁→床→同じ壁の関係を管理する。天井では下、床では上だけが戻る操作になる。

接写はゲームの面を変更せず、`Closeup` が独立した写真画面を表示する。下の三角で接写を閉じると、元の壁・天井・床がそのまま現れる。持ち物の表裏は `ItemCloseup`。設定・記録・ヒントは部屋画面から扱う。

`solve` は部屋の到達可否、依存する謎、取り付け部品、入力値の正しさを検証してから、一度だけ解除と報酬を適用する。UIから直接解除フラグを立てない。鍵・栓などの消耗品は `install` が所持品から取り付け済み一覧へ移す。

四枚の銘板を最終錠でまとめて確認する。電力復帰後に全室の天井の印を読めるため、到達済みの部屋にはいつでも戻れる。手掛かりは一度見れば記録から再確認できる。

## 機構

- 配電盤: 自分と上下左右のマンハッタン距離1の灯を反転。
- 配管: 各継手の辺を回転し、入口から出口まで9セルを通る閉じていない経路を検証。
- 計量槽: 水量を保存し、移動元が空または移動先が満杯になるまで移す。
- スライド: 空白に隣接するセルだけ移動。
- 連動輪: 押した輪と右隣の輪を8を法として1ずつ回す。
- その他: 入力列、ダイヤル、三重環、フィルムの並べ替え。

入力変更のたびに `solve` を通し、正解条件がそろうと機構が解除される。ダイヤルは巡回して再調整でき、配電盤・配管・入力列などには写真内の戻しねじがある。段階式ヒントは部屋の設定から任意で開く。

## 保存

`localStorage` の `zanshitsu:save:v1`。バージョン、部屋・面の範囲、数値列、アイテムID、水量保存、タイルの一意性などを検証する。壊れたJSON・未知のバージョンは新しい初期状態に戻す。保存失敗時は画面に通知する。

保存は同一オリジン・同一ブラウザ内。端末間同期は提供しない。バックグラウンドのタブ、タイトル、設定中、終了後はプレイ時間を加算しない。

## 表示と音

写真は `public/images/rooms/<room>/views|closeups|states` と `public/images/items/<item>/front|back.webp` に整理する。同じ材質の紙に共用する写真は `shared/` に置く。全一覧は `docs/photographs.json`。

操作対象は `SHAPES` の円・矩形・多角形。表示する輪郭とクリック判定は同じSVGジオメトリを使う。移動ボタンは写真の端へ寄せ、対象と干渉しないようにする。長方形の中心が図形内部とは限らないため、検証では塗り領域内の点を使う。

接写内の操作部品は `FRAMES` の写真座標に配置する。数字、針、水位、刻印などを写真の表面として描画し、写真の取得・開閉差分は状態から選ぶ。引き出し・キャビネット・箱の開閉とレンチ取得は遠景にも反映する。

音は明示的なユーザー操作で有効になる Web Audio。タブが非表示になったら環境音を止める。音だけを頼りにする謎はなく、五音の機構にも光点と段階がある。画面の動きはOS設定とゲーム設定の双方で減らせる。

## 検証

Vitestで機構の不変条件と全20段階の進行を確認。Playwright MCPでブラウザ上の実操作、スマホ幅の当たり判定、記録、持ち物、再読み込みと結末までを検証する。初見の難易度と所要時間は、自動化した解法の再生だけでは評価できない。
