# 設計

React + TypeScript + Vite の静的な一人用ゲーム。Node.js / pnpm は mise.toml で固定する。バックエンド・外部APIは使用しない。

## 進行と状態

4部屋、各6方向、20個の仕掛け。`data.ts` は配置・依存関係・解法、`engine.ts` は遷移と保存検証を担当する。

- `solve`: 正解を検証して解錠する。報酬・部屋移動を伴わない。
- `openContainer`: 解錠済みの収納を開く。
- `take`: 開いた収納の未取得アイテム、または床のレンチを取得する。
- `install`: 選択した物を正しい設置先に使う。レンチは残し、他の部品は所持品から設置先へ移す。
- `leaveRoom`: 解錠後にハンドルを押して移動する。最後の扉なら終了する。

`solved`、`opened`、`collected`、`installed`、`mounted` を分離して保存する。最終扉には四枚の銘板を一枚ずつ設置する。設置後も押せば表裏を確認できる。取得・設置の重複や、他の部屋での設置を許可しない。

選択中の持ち物と接写画面は一時的なUI状態。壁・天井・床・部屋・接写の切り替え、取得後に選択を解除する。アイテムの表裏確認からは直前の接写へ戻り、選択は解除される。天井・床への往復は `wallFace` を保持する。

## 仕掛け

- 灯: 自分と上下左右が反転する。
- 配管: 入口から出口まで全9個の継手を通る経路を検証する。
- 水槽: 容量8・5・3。移動元が空か移動先が満杯になるまで注ぐ。到達可能な16状態を列挙し、保存検証と写真カタログでも共有する。
- スライド: 空きに隣接する板だけを動かす。
- 連動輪: 自分と右隣の輪を8を法として進める。
- 時計: 写真の針を選んで文字盤を押す、または針をドラッグする。
- 入力列: 完成した誤入力の次の操作で新しい列を始める。

## 写真と操作

`PhotoCloseup.tsx` が未設置・設置済み・収納内に物がある・取得後の写真を選ぶ。`PhotoControls.tsx` は写真の部品を操作する。`mechanismPhotos.ts` が写真の百分率座標を保持する。

手掛かりの文字や図は写真に含める。可変の数字、継手、ランプ、針、透過板も生成した部品写真を使用する。水面は16枚の状態写真を切り替える。水槽の下部収納だけは同じ撮影位置の開閉写真の切り出しを重ね、上の水量を維持する。SVG/CSSで謎の線・文字・水面を描かない。

部屋のクリック領域とホバー輪郭は同一のSVG形状。接写の透明なボタンは実物の位置に合わせる。キーボードのフォーカスには輪郭を表示する。移動の三角、メニュー、持ち物などのUIは写真と分離する。

採用画像のカタログは `photoAssets.ts`、寸法・容量・ハッシュは `docs/photographs.json`。候補や生成元のPNGは配信しない。

## 保存と互換性

保存キーは既存の `zanshitsu:save:v1` を維持し、内容のバージョンを2へ移行する。旧保存の取得済み報酬や設置済み部品を推定し、再出現させない。保存の範囲、ID、数値列、到達可能な水量、板の一意性を検証する。

同一オリジン・同一ブラウザで再開可能。保存失敗は画面に通知する。端末間同期はない。音は明示操作で有効化し、非表示のタブでは止める。画面の動きはOS・ゲーム設定で減らせる。

## 検証

Vitestで機構の不変条件、20段階の進行、移行、写真参照を確認する。Playwright MCPとagent-browserで実画面・取得・設置・部屋移動・再読み込み・スマホ幅を確認する。初見の所要時間は自動解法の再生では評価しない。

### 操作範囲と補助表示

細い写真の部品は、見た目と同じ細さに操作範囲を制限しない。時計の針は全長に操作範囲を持ち、重なった状態でも選び分ける。工具は持ち手中央を含める。検証は先端だけでなく複数箇所から行う。

鏡と下部の錠は一つの接写。鏡文字の写真部品は正しい2715を左右反転して使う。設置前後・開閉後はそれぞれの写真の入力窓座標を使用する。

水槽の現在量・目標量は写真外の状態表示へ分離する。目標の刻印がある栓を設置して所持品から移した後も、目標を確認できる。

ヒントの表示ページはUI状態、既に開示した最大段階は保存状態。前のヒントに戻る操作で開示済み段階や集計を減らさない。

### 設置後の手掛かりと完成図の往復

設置済みの部品は接写中の持ち物欄と分けて写真を表示し、裏面を確認できる。これは再使用可能な持ち物ではなく、設置先に残った物の観察操作である。観察前のパネルと仕掛けの状態を保持して戻る。

利用可能な仕掛けを初めて開く際は `beginPuzzle` で初期値を保存し、以後はその値を使用する。完成図の閲覧は既読記録と表示パネルのみを変更する。進行・入力配列・解錠状態は変更しない。表示中の完成図は元の盤面へ直接戻る参照画面として扱う。

持ち物の選択だけで操作可能な仕掛けを無効にしない。機構を操作した場合は選択を解除する。部品未設置や前提未達の制限は `canAccess` が維持する。

### 一つのスクリーンで使う二段階の投影

第3室のスクリーンは東壁の一つの接触領域。透過板の解錠前は無投影、解錠後は光点、音の問題の解錠後は数字を既定表示する。後者では光点と数字を切り替えて再確認できる。`projection.ts` が段階と写真の対応を管理する。

`r3-film-clue` は既存保存の記録IDとして保持するが、独立した細い接触領域にはしない。記録からは選んだ方の投影を開き、進行後も以前の手掛かりを参照できる。映写機は西壁で東へ向け、作業机は南壁へ移した。

第4室の通電時は `revealCeilingPower` が元の壁を保持して天井へ視点を向ける。写真を消灯状態から点灯状態へ変え、短い通知を表示する。通電済みで天井の刻印が未確認の保存にも再開時に案内する。刻印の確認後や他の部屋からの再開では視点を強制変更しない。

### 帰室の固定手掛かりと最後の鍵

`r4-equations` と `r4-paper` は入室時から同じ写真を表示し、別の仕掛けの解錠で内容を書き換えない。広角の棚の紙も同じ内容に固定する。

小箱 `r4-memory` の報酬は `exitKey`。通常の `solve → openContainer → take → install` に沿って、箱の開蓋と鍵取得を分ける。取得前後と扉への挿入前後は専用写真を使う。最終錠は鍵の設置に加えて四枚の銘板を要求する。既存セーブで箱が開いていても鍵を取れる。v1の自動報酬移行では、旧版に存在しなかったこの鍵を推定取得済みにしない。
